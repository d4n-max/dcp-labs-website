Manual QA interview questions test more than definitions. A good interviewer wants to know whether you understand how software is tested, how bugs are communicated, how risk is prioritized, and how you think when requirements are unclear.

For beginners, the hardest part is often not finding questions. It is practicing them in a way that builds real recall. Reading a long answer once can feel productive, but interviews require you to explain concepts out loud, connect them to examples, and stay clear when a follow-up question changes the angle.

Use this list as a practice set. Answer each question in your own words before reading notes or sample answers. Mark the questions that feel weak, then review those again later.

## Manual testing basics

Start with the foundation. These questions help you explain what manual QA is and why it matters.

1. What is manual testing?
2. What is the difference between manual testing and automation testing?
3. Why is manual testing still useful when automation exists?
4. What is quality assurance in software development?
5. What is quality control, and how is it different from quality assurance?
6. What is the role of a QA tester on a software team?
7. What makes a good tester?
8. What is exploratory testing?
9. What is ad hoc testing?
10. What is usability testing?

When practicing these, keep answers short first. For example, explain manual testing as human review of software behavior against expectations, requirements, and real user workflows. Then add one example, such as checking whether a signup form handles valid input, missing fields, and clear error messages.

## Test cases and test scenarios

Interviewers often ask about test cases because they show how you turn requirements into checks.

11. What is a test case?
12. What is a test scenario?
13. What is the difference between a test case and a test scenario?
14. What information should a good test case include?
15. How do you write test cases from a requirement?
16. What is a positive test case?
17. What is a negative test case?
18. How would you test a login page?
19. How would you test a search box?
20. How would you test a checkout or payment form?

For scenario questions, avoid jumping straight to a long list. Start with categories: valid inputs, invalid inputs, empty fields, boundary values, permissions, error messages, browser or device behavior, and expected result. That structure helps you answer even when the feature is unfamiliar.

## Bug reports and defect handling

Bug-report questions test communication. A tester who finds a problem but cannot describe it clearly creates extra work for the team.

21. What is a bug?
22. What should be included in a bug report?
23. What is the difference between severity and priority?
24. Can a bug have high priority but low severity?
25. Can a bug have high severity but low priority?
26. What would you do if a developer says your bug is not reproducible?
27. What does "steps to reproduce" mean?
28. What is a defect life cycle?
29. What is bug triage?
30. How do screenshots, videos, logs, or environment details help a bug report?

A strong answer usually mentions evidence. Good bug reports include a clear title, environment, preconditions, steps to reproduce, expected result, actual result, attachments, and impact. You do not need to sound dramatic. The goal is to make the issue easy to verify and prioritize.

## Testing types and techniques

These manual QA interview questions check whether you understand common testing categories and when to use them.

31. What is functional testing?
32. What is non-functional testing?
33. What is regression testing?
34. What is smoke testing?
35. What is sanity testing?
36. What is acceptance testing?
37. What is boundary value analysis?
38. What is equivalence partitioning?
39. What is compatibility testing?
40. What is cross-browser testing?

Do not treat these as isolated vocabulary cards only. Practice each term with a simple example. For boundary value analysis, you might test an age field that accepts 18 to 65 by checking 17, 18, 65, and 66. For regression testing, you might retest login after a password-reset change because related authentication behavior could be affected.

## SDLC, STLC, and team workflow

QA work happens inside a broader development process. These questions show whether you understand how testing fits with planning, development, release, and support.

41. What is SDLC?
42. What is STLC?
43. What are the main phases of the testing life cycle?
44. What is a test plan?
45. What is a test strategy?
46. What is a requirement traceability matrix?
47. What would you do if requirements are incomplete?
48. How do you decide what to test first when time is limited?
49. How do QA testers work with developers and product managers?
50. What would you test before approving a build for release?

For workflow questions, interviewers often want judgment, not perfect theory. A practical answer can mention risk, user impact, recent code changes, core business flows, known problem areas, and deadline constraints. If requirements are incomplete, explain that you would ask clarifying questions, document assumptions, and test the visible behavior while flagging open risks.

## How to practice this list

Do not try to master all 50 questions in one sitting. Split them into small practice blocks:

- Day 1: manual testing basics
- Day 2: test cases and scenarios
- Day 3: bug reports and defect handling
- Day 4: testing types and techniques
- Day 5: SDLC, STLC, and workflow
- Day 6: review weak questions
- Day 7: run a short mock interview

For each question, use a simple answer structure:

1. Give a short definition.
2. Explain why it matters.
3. Add one practical example.
4. Mention a common mistake or tradeoff if relevant.

This keeps answers clear without turning them into memorized scripts.

## Turn weak answers into review prompts

After each practice session, write down the questions you could not answer clearly. Those are the questions worth reviewing, not the ones that already feel easy.

For example:

- "Severity vs priority" becomes a flashcard with two definitions and one example.
- "How to test a login page" becomes a checklist for valid login, invalid password, empty fields, locked account, password reset, error messages, and session behavior.
- "Incomplete requirements" becomes a short answer about clarifying questions, assumptions, risk, and communication.

## Final take

Manual QA interview preparation works best when you practice active recall. Read the question, answer out loud, check the gap, and review the weak spots later.

This list gives you 50 common manual QA interview questions, but the list alone is not the system. The system is repeated practice: definitions, examples, scenario thinking, bug-report clarity, and enough review to make your answers easier to retrieve when the interview starts.
